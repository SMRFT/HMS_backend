1. EXECUTIVE SUMMARY & THE CASH INVARIANT
================================================================================
In Shanmuga Hospital Management System (HMS), financial transactions are transacted
across multiple distinct clinical and administrative modules:
  - Out-Patient Registration & Consultations
  - Out-Patient Pharmacy
  - Diagnostic Lab & Radiology Investigations
  - In-Patient Advance Receipts
  - Final Discharge Clearances

To maintain absolute accounting integrity without cash breaks or discrepancies,
the hospital enforces the Core Counter Mathematical Invariant:

  ClosingBalance = OpeningBalance + collected_Amount - SalesReturnAmount

Where:
  * OpeningBalance     : Physical float handed over to the cashier at shift start.
  * collected_Amount   : All pure Cash collections during the shift
                         (Registration Cash + OP Pharmacy Cash + Investigation Cash
                          + IP Advance Cash + Final Discharge Cash + Misc Cash Receipts).
  * SalesReturnAmount  : All cash paid back to patients from the drawer
                         (Pharmacy Returns + Cancelled Test Refunds + Advance Refunds).
  * CreditAmount       : Digital tender (Credit/Debit Cards, UPI, Online transfers,
                         Cheques, Insurance Credit). These are tracked in banking
                         registers and do NOT enter the physical cash drawer.

--------------------------------------------------------------------------------
3.2 WHAT DOES NOT WORK PROPERLY & ACTUAL ROOT CAUSES
--------------------------------------------------------------------------------

ISSUE 1: Field Name Case Sensitivity (collected_Amount vs total_amount)
  - Actual Issue : hospital_cashcountershiftdetails uses 'collected_Amount'
                   (capital A). Legacy reports query 'total_amount' or 'collected_amount'.
  - Cash Impact  : Returns 0.00, falsely reporting that zero cash was collected.
  - Fix          : Standardize field lookup to:
                   doc.get('collected_Amount') ?? doc.get('collected_amount') ?? 0.00

ISSUE 2: Department Primary Key Discrepancies (Mismatched Join Fields)
  - Actual Issue :
      * OP Pharmacy  : Master voucher has bill_no="262702...", while pharmacybilling
                       has bill_no="262701..." and links via integer Bill_id.
      * Investigation: hospital_investbilling has bill_no=None! True key is investBillNo.
      * Registration : Uses bill_number instead of bill_no.
  - Cash Impact  : Accounts queries joining on bill_no drop records, reporting ₹0 revenue.
  - Fix          : Always use module-specific keys:
                   - Pharmacy: Bill_id
                   - Investigation: investBillNo
                   - Registration: bill_number
                   - IP Advance: advance_payments.bill_no

ISSUE 3: Default "Cash" Stamping on Mixed / Digital Payments
  - Actual Issue : Split tenders (e.g. ₹500 Cash + ₹1,000 UPI) stamp payment_mode="Cash"
                   on the parent counter voucher header.
  - Cash Impact  : Reports filtering payment_mode="Cash" overstate physical drawer cash.
  - Fix          : Parse payment_details.breakdown to strictly separate Cash from Digital.

ISSUE 4: Investigation Refunds & Advance Refunds Excluded from Shift Returns
  - Actual Issue : SalesReturnAmount historically only captured hospital_salesreturn.
                   Cash refunded for cancelled tests (hospital_investrefund) and IP
                   excess advance (hospital_ipadvance_refund) was omitted.
  - Cash Impact  : Physical drawer is short by the refunded amount against ClosingBalance.
  - Fix          : In calculate_shift_collection(), sum:
                   Total Returns = Pharmacy Returns + Invest Refunds + Advance Refunds.

ISSUE 5: Connection Pool Termination via client.close()
  - Actual Issue : Endpoints called client.close() in finally blocks, destroying the
                   shared singleton connection pool for other threads.
  - Cash Impact  : Subsequent API calls failed with WinError 10054 / 10060 socket drops.
  - Fix          : Removed client.close() from all handlers and added auto-reconnect.
